# Навігація назад у плануванні робіт

## Проблема

На сторінці конкретного плану `/work-planning/[id]` кнопка “До планування” вела на дефолтний `/work-planning`. Через це після переходу з `/work-planning?week=2026-08-20&view=category` користувач повертався не в той тиждень і режим перегляду.

Додатково server actions на сторінці плану після виконання редіректили назад на `/work-planning/[id]` без контексту, тому browser back після дій також міг вести в неочікуване місце.

## Як тепер передається returnTo

Посилання з карток планів на `/work-planning` тепер відкривають detail page з параметром:

```text
/work-planning/[id]?returnTo=/work-planning%3Fweek%3DYYYY-MM-DD%26view%3Dcategory
```

`returnTo` формується з вибраного робочого тижня і активного `view`.

## Оновлені посилання

Оновлено переходи з картки плану:

- кнопка редагування плану;
- кнопка відкриття/перегляду плану.

Обидві кнопки передають однаковий `returnTo`.

## Safe validation

На сторінці `/work-planning/[id]` і в server actions використовується safe validation:

- дозволяється тільки внутрішній шлях, який починається з `/work-planning`;
- `//...` не дозволяється;
- `http://...` і `https://...` не дозволяються.

Якщо `returnTo` невалідний, він ігнорується.

## Fallback без returnTo

Якщо план відкрито напряму без `returnTo`, кнопка “До планування” веде на тиждень самого плану:

```text
/work-planning?week=[work_plans.period_start YYYY-MM-DD]&view=category
```

Якщо план не знайдено, fallback: `/work-planning`.

## Actions після змін

Форми на сторінці плану передають hidden input `returnTo`, а server actions зберігають його у redirect:

- надіслати план;
- повторити невдалі надсилання;
- повторно надіслати всім;
- редагувати чернетку;
- скасувати план;
- прибрати заявку з плану;
- перенести заявку в інший план.

Це зберігає URL detail page у вигляді `/work-planning/[id]?returnTo=...&success=...` або `&error=...`, тому кнопка “До планування” не втрачає початковий тиждень/режим.

## Known issues

- Browser back усе ще залежить від історії браузера, але після server actions `returnTo` більше не губиться, тому in-app кнопка “До планування” має стабільний цільовий URL.
- Export плану відкривається окремим route `/work-planning/[id]/export`; для нього return navigation не змінювалась.
