# Закриття робочого тижня і оновлення планування

## Що робить кнопка “Оновити систему”

Кнопка **Оновити систему** на сторінці `/work-planning` приводить систему планування до поточного робочого тижня.

Дія:
- визначає поточний робочий тиждень через `lib/date/work-week.ts`;
- знаходить усі плани минулих робочих тижнів;
- переводить активні минулі плани у статус `done`;
- залишає у старих планах тільки заявки зі статусом `done`;
- виводить усі not-done заявки зі старих планів;
- створює або перевіряє draft-плани поточного робочого тижня без автоматичного carry-over.

## Що означає закриття тижня

Закритий минулий тиждень стає архівом виконаних робіт. Для цього використовується існуючий статус плану `done`, без нової міграції.

У UI статус `done` для плану показується як **Архів**.

## Done заявки

Якщо `ticket.status = done`, `work_plan_items` залишається у старому плані. Це історія виконаного тижня.

## Not-done заявки

Якщо `ticket.status != done`, зв’язок `work_plan_items` видаляється зі старого плану.

Ticket не видаляється і його status не змінюється.

Для кожної такої заявки пишеться `ticket_history`:
- action: `Виведено з плану`
- metadata.source: `week_close_refresh`
- metadata містить план, період і причину.

## Статуси для нового планування

Додавати в нові плани можна тільки робочі активні статуси:
- `new`
- `assigned`
- `in_progress`
- `waiting`
- `waiting_admin_confirmation`

Не додавати:
- `pending_review`
- `done`
- `rejected`
- `cancelled`

## Архів

Плани минулих тижнів не видаляються. Вони лишаються доступними у `/work-planning` за вибраним минулим тижнем і можуть експортуватися як історія.

## Зв’язок із dashboard “Оновити плани”

Після оновлення системи not-done заявки більше не мають активного `work_plan_item` у старих планах. Тому вони стають доступними в dashboard modal **Оновити плани** для додавання у поточний draft-план.

## Carry-over

Нова дія оновлення системи не викликає старий carry-over. Вона тільки створює або перевіряє draft-плани поточного робочого тижня.

Старий `ensureWeeklyDraftPlansForAutoRouting()` лишається для існуючих сценаріїв, але close-week action використовує окремий ensure без перенесення заявок.

## Known issues

- Старий carry-over усе ще існує в системі для інших сценаріїв. Потрібно окремо вирішити, чи залишати його після переходу на системне оновлення до поточного тижня.
- Status `done` використовується як архівний стан плану, бо новий `archived` потребував би міграції.
- Автоматичне додавання всіх активних not-done заявок у поточні плани поки не виконується, щоб не створити неправильні маршрути. Після очищення старих планів заявки додаються через dashboard modal.
