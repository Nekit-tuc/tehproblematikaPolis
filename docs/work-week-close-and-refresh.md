# Закриття робочого тижня і оновлення планування

## Що робить кнопка “Оновити систему”

Кнопка **Оновити систему** на сторінці `/work-planning` закриває вибраний робочий тиждень.

Дія:
- переводить активні плани вибраного тижня у статус `done`;
- залишає у старих планах тільки заявки зі статусом `done`;
- виводить усі not-done заявки зі старих планів;
- створює або перевіряє draft-плани наступного тижня без автоматичного carry-over.

## Що означає закриття тижня

Закритий тиждень стає архівом виконаних робіт. Для цього використовується існуючий статус плану `done`, без нової міграції.

У UI статус `done` для плану показується як **Архів**.

## Done заявки

Якщо `ticket.status = done`, `work_plan_items` залишається у старому плані. Це історія виконаного тижня.

## Not-done заявки

Якщо `ticket.status != done`, зв’язок `work_plan_items` видаляється зі старого плану.

Ticket не видаляється і його status не змінюється.

Для кожної такої заявки пишеться `ticket_history`:
- action: `Виведено з плану`
- metadata.source: `week_close_refresh`
- metadata містить план, період і причину.

## Статуси для нового планування

Додавати в нові плани можна тільки робочі активні статуси:
- `new`
- `assigned`
- `in_progress`
- `waiting`
- `waiting_admin_confirmation`

Не додавати:
- `pending_review`
- `done`
- `rejected`
- `cancelled`

## Архів

Плани закритого тижня не видаляються. Вони лишаються доступними у `/work-planning` за вибраним минулим тижнем і можуть експортуватися як історія.

## Зв’язок із dashboard “Оновити плани”

Після закриття тижня not-done заявки більше не мають активного `work_plan_item` у старому плані. Тому вони стають доступними в dashboard modal **Оновити плани** для додавання у поточний або наступний draft-план.

## Carry-over

Нова дія закриття тижня не викликає старий carry-over. Вона тільки створює або перевіряє draft-плани наступного тижня.

Старий `ensureWeeklyDraftPlansForAutoRouting()` лишається для існуючих сценаріїв, але close-week action використовує окремий ensure без перенесення заявок.

## Known issues

- Старий carry-over усе ще існує в системі для інших сценаріїв. Потрібно окремо вирішити, чи залишати його після переходу на ручне оновлення системи.
- Status `done` використовується як архівний стан плану, бо новий `archived` потребував би міграції.
- Перенесення заявки між конкретними планами не виконується в цьому flow. Спочатку тиждень закривається, потім заявки додаються заново через dashboard modal.
